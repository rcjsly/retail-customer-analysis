# 指标与数据字典

## 数据链路
官方ZIP → 完整原始XLSX与manifest → classified_lines（SQLite）→ SQL/Python汇总 → CSV、报告与HTML。
原始粒度：一张发票中的一个商品或其他记账项目；不是一行一个订单。派生source_row等于原Excel行号（表头下一行为2）。

|原字段|含义|处理|
|---|---|---|
|InvoiceNo|发票号，C开头表示取消相关记录|按文本读取，去首尾空格；不能把每行当一单|
|StockCode|商品/项目编码|按文本保留；商品代理规则为五位数字加可选字母|
|Description|商品描述|原样保留，不作为唯一键，不靠文本补造类别|
|Quantity|数量|保留正负；负向另行分析|
|InvoiceDate|发票时间|保留来源时间，不擅自时区换算|
|UnitPrice|单价，英镑|非正单价单列，不填造价格|
|CustomerID|客户编号|缺失不填补；已知ID不等于自然人|
|Country|客户国家/地区|按原始字段分组，不推断发货地址|

## 逐行分区，按优先级互斥
1. invalid：日期、发票、编码、数量或单价关键字段无效。
2. non_merchandise：不符合五位数字加可选字母的商品代理编码，包括运费、服务、费用和部分特殊编码。此规则需实数抽查，可漏掉有效商品，不代表官方品类标注。
3. nonpositive_price：单价≤0。
4. zero_quantity：数量为0。
5. credit：数量<0且单价>0的商品行；含取消、冲销及其他负向记录，不全部称作退款。
6. cancellation_conflict：数量>0、单价>0但发票号C开头，单独核查。
7. sale：数量>0、单价>0且非C开头的商品行。

所有行保留分区，quality_partition.csv展示分区数量与金额。不会把缺失CustomerID作为经营交易的删除条件。

## 指标口径
|指标|分子/定义|分母/边界|
|---|---|---|
|正向商品销售额|sale行Quantity×UnitPrice之和|发票金额，未核实支付和履约|
|负向商品金额|credit行金额的绝对值合计|不是原订单匹配退款金额|
|记账净额|正向销售额−负向商品金额|按本次交易发生时间，不匹配原销售期|
|正向商品订单|sale内去重InvoiceNo|同单多行只计一次|
|客单价|正向商品销售额|正向商品订单数|
|已知客户|sale中非缺失CustomerID去重|未知客户不计入分母|
|客户销售覆盖率|sale中非缺失ID金额|全部sale金额|
|观察窗多单客户比例|已知客户中不同发票数≥2的人数|观察窗所有已知购买客户；各人的观察时长不等|
|90天再次购买率|首次观察发票后0至90×24小时内有另一发票的客户|首次观察日期≤来源末日零点−90天的已知客户；保守保证完整窗口|
|月度Cohort留存|该首次观察月份客户，在第k个自然月仍有sale的人数|同一首次观察月份客户数；不是连续购买或二购率|
|客户集中度|销售额前ceil(客户数×1%)位的sale金额|已知客户sale金额|
|商品销售占比|该StockCode的sale金额|全部sale金额|

90天复购允许同日不同发票，不把同一发票中的其他行当再次购买。首次出现不等于真实首次获客。最后自然月不完整，不进入月度留存矩阵；可观察但无人回购的格子为0，尚未观察的未来格子保留空白。

## 去重与异常
原始8字段完全相同标记为duplicate_candidate。源数据没有可验证的唯一行ID，因此基准不直接删重复候选，同时报告删除候选后的金额敏感性。极大订单、大量负向行不自动删除，输出原始发票供核验。基准报告必须说明此选择对结论的影响。

## 核对
分区总行数=原始行数；SQL月度金额=Python明细金额；客户金额=已知ID交易金额；月份订单数去重；同发票不能对应多个非空客户ID；销售变动分解加总=实际变动。金额容差0.01英镑（浮点计算），计数精确相等。
